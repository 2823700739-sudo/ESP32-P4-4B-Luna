# 首次设置 Luna 天气

手机优先：新 `2026.11.28` 使用 [手机热点设置](PHONE-SETUP.md)，时钟/天气无需电脑脚本。本页保留可选 BLE 兼容入口；正常 Start-Luna 不再询问天气。

当前 **2026.11.28 定版**保留此加密认证 BLE 配置入口；旧 `v2026.11.25-preview` 不支持，脚本会在询问密码前提示升级。普通用户优先使用手机网页；实际验证范围见本版清单。

## 三步设置

1. **使用新固件并配对 Luna。** 已有相同 Luna 分区布局的设备只更新新 `luna-panel.bin`，地址 **0x20000**，保留配对；新设备才使用新合并 bin 从 **0x0** 首装。合并包会清除原有配对、Wi-Fi 设置和天气地点/缓存。不要刷 C6，也不要整片擦除。保持 DC 供电，在 Windows 设置中完成 Luna 数字配对。
2. **双击兼容脚本。** 安装 Python 3.11 x64，完整解压配套 Windows 使用包，双击 **Configure-Weather.cmd** 修改配置。仅配置天气不会为原本未运行的电脑常驻注册或启动登录任务；手机设置无需运行此脚本。
3. **填写城市和网络。** 搜索城市并从候选列表选择正确省份/国家，再输入 **2.4 GHz Wi-Fi 名称与密码**。密码输入时不显示；确认后保存到 Luna。脚本分别报告保存、联网和天气更新结果，不要求填写 API Key。

配置成功后，设备自己通过 Wi-Fi / HTTPS 获取 Open-Meteo 天气，不依赖电脑转发天气数据。设置会保留到下次断电启动；更换 Wi-Fi 或城市时重新运行配置向导即可。当前时区仍为北京时间。

## 看到这些提示时

- **固件没有 weather setup**：当前设备还是旧固件，先更新新 app；不是重装 Python 或反复配对能解决的问题。
- **已有天气配置，是否更改**：回车保留；输入 `y` 修改。脚本不会自动覆盖已有设置。
- **已保存，尚未连上 Wi-Fi**：请检查 2.4 GHz、SSID 大小写及密码；设备会继续重试，也可重新运行向导修改。
- **Wi-Fi 初始化未成功**：当前板载 C6 的 Wi-Fi 兼容性可能不满足，保存不等于已联网；不要自动刷 C6。向维护者提供状态，勿提供密码。
- **Wi-Fi 已连接，尚未取得最新天气**：设备会继续重试。检查网络是否能访问 Open-Meteo；BLE 校时需要成功，HTTPS 才能验证证书。
- **城市查询失败**：改用拼音/英文名，或输入 `m` 手动填写城市名、纬度和经度。选择 `q` 取消，不会修改设备。
- **发送后超时/断线**：结果可能不确定，勿反复发送。重新打开向导先读取设备配置；它不会自动重放上次写入。
- **其他文件夹已有常驻**：使用原安装目录的向导，或明确卸载原目录任务再迁移。脚本不会覆盖其他目录的常驻。当前目录常驻正在运行时，天气向导会暂停它，并在退出后恢复；不会操控播放或音量。

## 数据与存储

城市搜索向 [Open-Meteo Geocoding](https://open-meteo.com/en/docs/geocoding-api) 发送城市查询词，不发送 Wi-Fi 信息；城市数据来自 [GeoNames](https://www.geonames.org/)。Wi-Fi 和地点只经已配对、加密认证的 BLE 写到设备，密码不作为命令行参数、不保存到电脑文件，也不会在设备回复中返回。它会保存在 P4 的 NVS，当前固件未宣称提供 Flash/NVS 静态加密；能读取设备 Flash 的人可能获得配置，不要分发设备存储镜像。

`luna_setup/weather_v1` 是包含版本、配置编号、Wi-Fi 与地点的单一记录；成功保存后设备后台应用，旧天气缓存格式保持兼容。公开 bin 仍无个人网络配置。`-PrepareOnly` 仅用于电脑依赖准备，不连接设备、不触发向导，不属于配网验收。

天气数据及城市服务须遵守 [Open-Meteo 的条款与署名要求](https://open-meteo.com/en/terms)。完整刷写与排障参见 [部署教程](https://github.com/2823700739-sudo/ESP32-P4-4B-Luna/blob/main/docs/DEPLOYMENT.md)；旧版本教程中的“没有入口”描述针对旧 bin，不代表当前定版。
