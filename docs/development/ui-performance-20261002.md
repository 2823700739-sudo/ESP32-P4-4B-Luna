# Luna 性能、稳定性与代码清理

更新：2026-10-03。当前状态见[current-status.md](current-status.md)。

## 显示与刷新

采用适配器支持的 DOUBLE_DIRECT 双缓冲，LVGL 同步脏区域，避免三缓冲局部复制路径的旧数字问题。上一版用户已确认无问题；不是所有显示问题都归因于同一原因。正常界面 33 ms 回调、15 ms 刷新轮询，CPU 始终 360 MHz；不全屏逐帧重画、不改 SDK/托管驱动、不盲目开启 PPA。

全量 16/28 px 中文字体保留互斥解码，其余常用字体/数字不压缩。真实 LVGL 12,000 次并行解码试验曾复现共享解码状态竞争；受保护版无损坏。保留两个软件绘制线程与性能编译配置，不裁掉当前中文支持。

本轮只更新当前卡片：时钟/天气/额度/电脑布局互不后台更新；音乐仍持续读取状态维持连接标识，但只在音乐卡绘制业务内容。切卡或返回重置更新期限，确保显示最新数据。相同文字、图片和透明度不重复设置；移除重复标题/歌手缓冲与基于整个结构体 memcmp 的变化判定。

单次场景/切卡完成完整重绘保留，普通宠物、星星和 ZZZ 仍局部刷新。小猫路径/交互、手动/自动待机、音量外点行为不变。

## Windows 常驻与稳定性

音乐和指标采集不在 BLE 收发线程里执行。Codex 仅保留额度窗口数据，删除旧 thread/list 工程查询、旧摘要/重置文案与完整路径缓存。响应队列上限 32，丢弃无关通知、无效 JSON 对象；迟到响应洪泛不造成无限增长，EOF 信号仍能投递。

媒体元数据请求最多等待 2 秒；超时返回不可用并允许后续轮询恢复。动作调用超时会取消仍排队的协程，避免很晚才执行。已交给 Windows 的操作不能保证撤销，继续记录不确定结果且不重放。保留快速播放/暂停代际对齐与常驻进程恢复。

旧 HTTP 动作解析器、toggle/音量增减白名单分支已删除；当前 BLE 的六种明确动作和去重历史保留。三项未被固件读取的 Kconfig 设置（旧 Wi-Fi 最大重试、NTP server、timezone）删除，现有实际行为不变：前三次即时重试后 30 秒恢复、pool.ntp.org、CST-8。

旧音频/麦克风/OTG/HTTP/封面代码在前轮已移除；其含未提交内容的 35 个文件及旧运行数据已在仓库外保留本地恢复副本。不为清理依赖列表而修改 BSP，未初始化的可选驱动不等于正在消耗运行性能。
