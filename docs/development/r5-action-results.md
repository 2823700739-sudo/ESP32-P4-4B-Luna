# R5：动作防重放与真实结果

USB 与 Wi-Fi HTTP 共用 Windows Agent 的动作记录，不建立两套各自独立的去重表。正式固件仍遵守单活传输规则：已发出的 USB 动作不因为超时而跨通道重发。本轮不增加自动重试。

## 行为

- 新的有效白名单动作记录请求编号、动作名和参数，最多保存 128 条；
- 相同编号、相同内容且已完成：返回第一次结果的独立副本，`duplicate=true`，包括失败或未确认结果；
- 相同编号但动作或参数不同：返回 `request_id_conflict`，不执行新动作；
- 相同请求仍在执行：立即返回 `action_in_progress`，不阻塞等待、不误报成功；
- Windows 操作抛出异常或超时：返回 `action_result_unknown` 和 `result_known=false`，保存该结果；不追加媒体键，也不自动重试；
- 媒体接口明确返回未接受时，原有白名单媒体键回退保留；显式播放/暂停没有模糊的切换键回退；
- 请求对象和字段必须类型正确，不能把 null、数组或数字转换成合法编号或动作名；设置音量只接受 0–100 整数，其他动作不接受额外的非空参数。

`ok=true` 表示调用被接受或媒体键已提交，不保证播放器已经完成异步状态变化。最终播放状态仍以 GSMTC 后续同步为准。未确认结果也不代表动作肯定没有执行，不能据此重复发送切歌或静音切换。

缓存只在当前 Agent 进程内有效，USB 重连不会清空，Agent 重启会清空。容量满时淘汰最早的已完成记录；不会淘汰正在执行的记录，全部未完成时返回 `action_history_busy`。很旧的编号被淘汰后不再具备防重放保证，因此发送方必须为每个新动作生成新编号，不能在 Agent 重启后重放旧请求。

## 诊断与记录

鉴权的 `GET /api/v1/diagnostics` 新增 `actions`：接收、实际执行、成功、失败、未确认、重复、处理中重复、编号冲突、校验拒绝、容量忙和当前待完成数量，以及最近/最长动作处理毫秒数。动作结果记录的锁不跨越 Windows API 调用，不阻塞 PC 状态缓存读取。

`monitor-link.ps1` 将动作统计写入 CSV，同一 Agent 运行期间失败或未确认计数增长会报告异常。历史计数作为首次基线，旧 Agent 未提供 `actions` 时字段留空，原有链路记录仍可用。

处理耗时从 Agent 开始执行到生成结果，包含 Windows 调用和读取状态，不包含板端触摸、排队、USB 上行与屏幕刷新，不能用它宣称触摸到响应的 300 ms 验收通过。

## 验证

本轮只更新 Windows Agent 与记录脚本，固件协议保持兼容，无需重新烧录。

2026-10-02：47 项 PC Agent 单元测试通过，新增回归覆盖失败结果回放、不同动作/参数编号冲突、处理中重复请求、超时不追加媒体键、音量读回异常不重放、结果副本隔离、缓存容量及待完成记录保护、动作耗时统计和严格请求校验（包括过长或过深 JSON）。使用本机临时 HTTP 服务与模拟 USB 串口验证了跨通道共用结果，以及不合法 JSON 对象在两个通道均返回错误；这些测试使用模拟媒体和音量适配器，不改变真实播放器。

CSV 脚本解析通过；模拟诊断验证了失败计数增长和未确认计数增长均报告异常，正常重复计数增长不误报异常，旧 Agent 缺少动作统计时字段留空。

新 CSV 脚本在 Windows PowerShell 5.1 下连接仍在运行的旧 Agent，3 秒得到 4 次正常实机链路采样、0 次异常。这仅验证脚本向后兼容与原有 USB 链路，不能作为新版动作逻辑已部署的证据。

当前执行策略拒绝了本轮 Agent 重启验证，旧后台助手保持运行，因此尚不能把新版动作逻辑称为已在 COM28 部署或实机通过。手动加载新版：

```powershell
.\pc-agent\manage-autostart.ps1 -Mode stop
.\pc-agent\manage-autostart.ps1 -Mode start
```
