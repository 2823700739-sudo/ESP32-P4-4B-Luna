# R5 稳定性与诊断：首批改动

Wi-Fi 连续连接失败达到 `LUNA_WIFI_MAXIMUM_RETRY` 后，不再永久停止重连。固件保留前几次即时重试；达到上限后每 30 秒尝试一次，取得 IP 后清零计数。Wi-Fi 离线时天气保留缓存，USB PC 链路不受该重试策略控制。

现有 Diagnostics 页增加运行时长、内部 RAM 当前空闲量及历史最低空闲量，供 8 小时运行记录使用。最低空闲量不能单独证明无内存泄漏，应同时观察一段稳定负载下的趋势。

## Windows Agent 登录自启动

Windows 当前用户登录后自动启动 Agent，由 Agent 常驻等待 OTG 插入；USB 本身不会直接启动 Windows 程序。计划任务使用交互式用户令牌、忽略同一任务重复启动，并有 Agent 命名互斥锁防止手动启动与计划任务同时抢占 COM28。任务直接运行后台 Python 入口，停止任务时不会留下持有 COM28 的子进程。`pc-agent/manage-autostart.ps1` 可安装、查看、启动、临时停止和移除任务；后台日志写入 `pc-agent/agent.log`。

2026-10-01：本机已注册 `Luna PC Agent` 登录任务，确认交互式用户、无限运行时限和重复任务忽略策略；18 项 PC Agent 测试通过，包括互斥锁重复启动测试。手动启动与计划任务竞争时，第二个实例正常退出；由任务启动时，HTTP `/health` 返回成功，COM28 完成 USB 握手与状态快照；停止任务后 COM28 可重新打开，重新启动任务后再次连接。下一次 Windows 重新登录后的自动启动、实际 OTG 拔插恢复仍待实测。

## USB 链路计数

Diagnostics 页新增从本次固件启动起累计的 CDC 打开次数、Luna Link 握手次数、请求成功/失败、超时、协议错误、内部队列丢弃和发送错误。`opens` 是主机打开 CDC 时 DTR 从低到高的次数，不能直接等同物理拔插次数。协议错误包含无匹配应答、坏帧、CRC 错误和接收溢出。计数只供诊断，不改变现有链路和动作决策。

2026-10-01：固件 `c330772` 通过 ESP-IDF 6.0.2 构建，经 COM27 写入并通过哈希校验。烧录复位后，后台 Agent 在 COM28 重新完成握手；出现过短暂的枚举断开与恢复，此后观察约 20 秒未新增连接错误。仍需目视确认诊断文字不遮挡按钮，再通过实际 OTG 拔插、短时断线和正常状态轮询观察计数变化；烧录成功和一次握手不能代替这些验收。

## Agent 侧链路观测

2026-10-01：PC Agent 增加鉴权的 `GET /api/v1/diagnostics`，记录本次进程内的 USB 连接会话、重连错误、当前连接时长和成功回复的状态/动作/封面请求数。USB 工作线程遇到未预期的 Python 异常时记录错误并继续重试，避免线程静默退出。`pc-agent/monitor-link.ps1` 只轮询本机 HTTP 接口，不争用 COM28，可输出 CSV 用于 8 小时运行观察。21 项 PC Agent 单元测试通过；重启 Agent 时一次 12 秒采样记录到 2 次 HTTP 拒绝连接，随后 COM28 正常握手；稳定后一次 9 秒采样有 4 次连接正常、0 次失败，再次 3 秒采样也有 4 次连接正常、0 次失败。短时实测不能代替实际 8 小时、OTG 拔插和 UI 目视验收。

随后补上“串口仍打开但无有效帧”的空闲超时：握手后 120 秒无 Luna Link 帧，Agent 记录错误、关闭会话并重新发现设备。阈值高于固件允许的最长 60 秒状态轮询间隔。诊断接口新增最近帧时间和帧年龄；CSV 同时记录 Agent 启动时间，能识别采样期间 Agent 重启及计数清零。24 项 PC Agent 单元测试通过，其中包括空闲超时、正常帧重置计时和默认阈值边界测试。真实设备的 120 秒停帧恢复仍待故障注入验证。

新 Agent 重启后再次在 COM28 完成握手；随后 12 秒记录了 5 次正常采样、0 次断线或错误，状态请求从 1 增至 4，最近帧年龄在 0.3–4.5 秒之间。后台计划任务保持运行。此观察确认正常轮询不会触发空闲重连，但不证明实际停帧故障恢复。

另用模拟的诊断响应让 `agent_started_at` 在相邻采样间变化：CSV 正确记录 `Agent restarted` 并返回失败；此测试没有重启真实 Agent 或占用 COM28。

最终阈值调整到 120 秒并重新启动计划任务加载配置：诊断接口返回 `idle_timeout_seconds=120`，COM28 已连接，状态请求继续增长，最近帧年龄约 0.2 秒且无断线/错误。较早 30 秒阈值版本的短时观测不用于 60 秒低频轮询的验收。

## PC 来源卡牌的离线保护

Codex 与音乐卡在 PC 链路待连接时显示 `WAITING FOR PC`；链路失败后有旧数据则显示 `PC OFFLINE - LAST KNOWN`，从未收到数据则显示 `PC OFFLINE - NO DATA`。音乐播放、切歌、音量弹窗、静音和滑块在 PC 链路离线时禁用，触控回调也再次检查链路状态，避免旧的“可操作”状态误导用户；Wi-Fi 天气与本地时钟不跟随 PC 状态禁用。卡牌被轮播销毁后重新创建时，徽标和按钮状态从当前链路状态恢复。

2026-10-01：ESP-IDF 6.0.2 构建通过；最终应用镜像 SHA-256 为 `962B938421285A833E69964A7357217C007C1A0BE333958ADFBE837D6F3CDEEA`。通过 COM27 烧录并完成哈希校验，后台 Agent 随后在 COM28 重新握手。首次烧录期间 Agent 记录了设备暂时未枚举的重试错误；恢复后再观察 20 秒，状态请求从 138 增至 142，错误数保持 35、断线数保持 1。为区分“离线无旧数据”又补上 `PC OFFLINE - NO DATA` 后再次烧录；Agent 再次重连，连接会话数为 3、断线数为 2、状态请求数为 170。徽标位置、各按钮禁用状态及 Wi-Fi 回退时是否正确恢复，仍待屏幕目视与触控验收。

最终固件重连稳定后，12 秒链路监测得到 5 次正常采样、0 次新断线或错误；烧录期间累计的错误不等于恢复后的持续故障。

构建脚本现在遮盖 ESP-IDF 非交互式构建、重配与烧录输出中的本地 Wi-Fi 和 Agent 配置行；实际 `reconfigure` 输出验证了凭据行被遮盖。`menuconfig` 为交互配置界面，不属于该输出过滤范围。

## 设备运行状态同步到 Windows

2026-10-02：固件增加无需应答的 USB 诊断快照，Agent 与 CSV 可记录设备启动 ID、运行时间、重启原因、固件 ELF 哈希、内部 RAM/PSRAM 和固件 USB 计数，断线、重连尚无新快照或超过 120 秒未更新时标记为过期。30 项 PC Agent 测试通过；已构建、烧录并读取实板快照，主动 EN 复位后正确检测启动 ID 变化与自动重连。详细记录及长时采样命令见 [USB 设备运行状态同步](r5-device-diagnostics.md)。8 小时运行与实际拔插仍待验收。

实机诊断发现 Codex App Server 的同步读取会阻塞 USB 状态响应；已移至后台，失败或过期额度不伪装为实时数据。稳定 30 秒采样未新增 USB 错误，服务自身超时仍可能发生。Agent 停止脚本也加入等待其后台进程退出，避免快速 stop/start 时新实例被尚未释放的互斥锁拦截；本机连续停止后立即启动已验证成功。构建输出遮盖补上 `Using default value from sdkconfig` 的续行，实际重配输出检查未发现本地凭据值。
