# P1 联网天气卡与离线缓存实机验证

> 天气数据检查仍适用；本页的三卡滑动步骤已过时，当前轮播步骤见
> [壁纸时钟卡实机验证](p1-clock-card.md)。

## 本轮目标

本轮接入按固定经纬度查询的天气卡，验证以下内容：

- 当前天气、温度和配置地点；
- 体感温度、湿度、风速、今日最高和最低温；
- 今日最高降水概率、经纬度和天气更新时间；
- 外网请求在后台进行，不阻塞面板的 PC 状态轮询；
- 天气服务或电脑连接中断时保留最后数据，并显示黄色 `CACHED`；
- 卡片显示 `Weather data: Open-Meteo` 数据来源。

数据来自 [Open-Meteo Forecast API](https://open-meteo.com/en/docs)。当前个人原型
使用无需 API Key 的非商业接口，默认每 20 分钟请求一次。

## 第一步：录入地点和经纬度

开发板没有 GPS，天气位置不会自动推断。先查询自己的十进制经纬度，然后在
项目根目录执行，替换命令中的地点和数值：

```powershell
cd D:\Documents\ChatGPT\ESP32-P4-4B-Luna
.\pc-agent\set-weather.ps1 -Location "地点名称" -Latitude <纬度> -Longitude <经度>
```

北纬和东经使用正数，南纬和西经使用负数。脚本只修改被 Git 忽略的
`config.local.json`，不会覆盖配对令牌或其他设置。面板把坐标显示到小数点后
四位，仅用于标识配置位置。

## 第二步：重启 Windows 助手

在原助手窗口按 `Ctrl+C`，然后重新启动：

```powershell
.\pc-agent\start-agent.ps1
```

位置配置正确时应出现：

```text
Open-Meteo weather synchronization is active.
```

如果显示 `Weather location is not configured`，重新检查地点、纬度和经度是否
已经写入 `pc-agent/config.local.json`。天气请求在后台执行，助手启动后等待数秒
再观察天气卡。

## 第三步：烧录最新完整镜像

连接开发板 USB 转串口接口后执行：

```powershell
.\scripts\build-firmware.ps1 -Action flash-full -Port COM27
```

必须使用 `flash-full` 将完整镜像从 `0x0` 写入。烧录后可查看日志：

```powershell
.\scripts\build-firmware.ps1 -Action monitor -Port COM27
```

## 第四步：验证实时天气

1. 等待顶栏 PC 状态变为就绪；
2. 向左滑动到 `WEATHER` 卡；
3. 确认温度、中文天气状况和地点名称正确显示；
4. 核对体感温度、湿度、风速、最高和最低温、降水概率；
5. 核对纬度和经度与配置一致，保留四位小数；
6. 确认底部显示 Open-Meteo 来源和更新时间；
7. 在三张卡片间往返滑动 20 次，确认没有复位或内容错位。

天气模型数据与手机天气应用的数据源、网格和更新时间可能不同，数值不要求
完全相等。本轮主要核对字段完整性、位置正确性和刷新稳定性。

## 第五步：验证缓存和恢复

1. 在实时天气正常显示后，确认 `pc-agent/weather-cache.json` 已生成；
2. 暂时断开 Windows 外网，保持电脑与面板局域网连接；
3. 重启 Windows 助手；
4. 天气卡应继续显示最后一次成功数据，温度变为黄色并出现 `CACHED`；
5. 恢复外网连接；
6. 为避免等待 20 分钟，可重启一次助手触发立即刷新；
7. 刷新成功后 `CACHED` 消失，温度恢复蓝色。

如果直接让电脑休眠，面板无法收到新的 PC 状态，但会保留内存中的最后天气
数据并转为缓存状态。开发板断电后本轮仍需要 Windows 助手重新发送磁盘缓存；
把缓存持久化到 TF 卡留到 TF 卡功能单独恢复后处理。
