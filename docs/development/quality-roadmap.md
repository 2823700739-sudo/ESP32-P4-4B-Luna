# Luna 持续打磨与发布质量门槛

更新：2026-10-04。用户最新要求先暂停优化，转向 GitHub 发布检查与文档整理；自动化 luna 已核对为 PAUSED。以下工作顺序保留供后续明确恢复时参考，不再授权自动推进功能。暂停不表示达到发布标准；实际证据以[当前开发状态](current-status.md)为准。

## 不变的产品定位

Luna 是常亮、DC 供电的无线桌面伙伴：安全 BLE 负责 Windows 音乐与状态，Wi-Fi 负责独立天气与备用校时。保留已确认的繁星背景、像素猫、五卡横滑、三针待机时钟和现有交互。不恢复 OTG、语音、麦克风、封面或重复的旧卡片方案。

创新应围绕“抬眼看懂、触摸有反馈、离线也有陪伴”完善现有体验，而非堆积功能。新服务、驱动、收费依赖、账号权限、破坏性升级和主体视觉重设计需要用户决定。

## 工作顺序

1. **可靠性与真实数据**：明确启动、断线、数据过期、超时和恢复边界。读数不可用不冒充零，控制动作不重放；可恢复故障不能拖垮其他采集器。
2. **性能与资源**：可见卡片按需更新、动效局部刷新；限制队列、日志、缓存、后台任务与资源寿命。保留稳定的 DOUBLE_DIRECT 双缓冲、字体互斥及 360 MHz，性能判断依靠测量。
3. **交互与美观**：逐步统一字号、间距、状态反馈、动效节奏与触控命中范围；逐项对照已确认预览与实机。不把模拟截图等同于实机效果。
4. **Luna 的辨识度**：在现有猫、星空、天气与时钟中完善细腻、可理解的动态反馈；避免抢占触控、遮挡数据或增加大面积刷新。影响主要操作习惯的新交互先确认。
5. **代码与测试**：按实际职责收拢模块、清理未使用的本项目代码；保留兼容现有 C6 的必要维护路径。为每个修复补回归，新增跨线程/协议改动必须验证失败边界。
6. **公开维护体验**：清晰的硬件清单、版本矩阵、可复现构建与安装步骤、排障、架构和协议说明、素材来源与许可、示例配置以及可运行的测试/CI。公开发布前检查隐私、凭据和分发许可；项目许可证需明确选择，不擅自代用户授权。

## 每轮实施规则

每轮先检查现有改动和日志，选择一个有价值的小范围问题；记录依据、改动、测试、实际部署与未验证项。没有证据时先检查，不为了持续执行制造重构。共享工作区中的未提交内容不得覆盖。

已建立每小时独立定时任务，但最新核对为 PAUSED；保留原调度与本地项目配置。仅在用户明确恢复后依照本页推进；需要实机操作、产品取舍或新权限时明确提问。无新增可行动结果时不重复汇报。任务模式可能在应用中更改，后续以实际配置为准。

默认只修改、构建和测试本项目。必要的本项目 BLE 常驻重启后检查恢复；不自动推送 GitHub、不操控真实音乐做回归，不擦除 NVS/TF/C6，不长期占用 COM27。固件部署只采用已验证的安全流程，不把安装成功当作实机验收。

### 每轮交接、复盘与经验沉淀

每次执行先读取根目录 [HANDOFF.md](../../HANDOFF.md)，再核对现有状态、质量路线与项目经验，不把旧对话当作唯一上下文。

每完成一部分、结束运行或遇到需要配合的阻塞时，按顺序收尾：

1. 更新 `HANDOFF.md`：当前在做什么、已经完成了什么、现在卡在哪里、下一步准备怎么做、已经验证不能再走的弯路。写给没有上下文的新会话，补齐相关文件、命令、验证/部署范围及安全边界；无阻塞明确写无。不要写凭据。
2. 更新 [collaboration-retrospective.md](collaboration-retrospective.md)，并在本次完成报告输出三列表格：修改内容、问题归因、下次开头应该补充的指令。依据本轮实际用户纠正，判断是信息不足/后来补充，还是信息已经足够但助手判断有误；需求变更不责怪用户。没有纠正时明确写无，不虚构错误；相同问题更新原条目。
3. 检查 [project-experience.md](project-experience.md)，仅保留以后会复用的纠错/有效方法，记录适用条件及证据。相似经验更新原编号；已有规则或模板只引用，不重复记录。没有新的可复用经验时说明“无新增”，不强行写条目。
4. 同步当前状态，在完成报告给出交接与复盘文件位置，以及经验文件和本轮新增/更新的具体编号；有意义的代码阶段不能省略收尾。

新会话第一句固定为：

> 请先读取 `HANDOFF.md`，了解项目现状，再继续推进。

这只是接手指令，不授权自动另开会话。自动化每次运行的提示词也必须先读交接文件。无改动、无新发现的纯检查不制造重复经验或复盘，但若状态或阻塞改变，仍需更新交接。

## 发布门槛

- 新环境能够按文档完成构建与 Windows Agent 安装，支持版本与硬件限制清楚；不依赖开发者机器上的私有绝对路径。
- 本地完整回归、实际运行 Python 环境测试、真实 LVGL/字体/协议验证均可复现，并有适合托管环境的测试入口。
- 实机完成 8 小时持续运行与 100 次切卡，检查内存/任务栈趋势、显示残影、触摸与待机往返；记录结果与测试条件。
- 完成 Windows 登录自启、设备断电重连、蓝牙异常及 Windows 睡眠/唤醒恢复检查；动作不会因重连重放。
- 五张卡片均显示来源明确的真实状态，缺失、过期与离线反馈一致；主要控件、小猫气泡和待机动画没有裁切/遮挡。
- README、当前状态、配置示例、维护/排障文档与实际实现一致；没有遗留路线的活动入口、隐私凭据或来源不明的发布素材。
- 用户验收当前视觉与核心交互，未完成的可选能力和已知限制明确列出。

满足门槛后整理证据与已知限制，提交给用户做公开发布决定，并结束本轮持续优化。GitHub 的“优质”没有客观排名保证；以可复现、可维护和实际使用体验为判断依据。
