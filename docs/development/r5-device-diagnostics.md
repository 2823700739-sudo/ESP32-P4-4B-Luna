# R5：USB 设备运行状态同步

Luna 在 USB 已握手时，随 PC 状态轮询发送一条 `DEVICE_DIAGNOSTICS`（类型 14）消息。Windows Agent 保存最近的有效快照，并在鉴权的 `GET /api/v1/diagnostics` 中通过 `usb.device` 提供这些数据。该消息无需应答；快照发送失败不阻止原有状态请求。

## 可以观察的数据

- 本次设备启动的随机 `boot_id`、运行秒数、重启原因和固件 ELF SHA-256；
- 内部 RAM 当前空闲量、历史最低空闲量与当前最大连续空闲块；
- PSRAM 当前空闲量与历史最低空闲量；
- Wi-Fi 是否已取得 IP，以及固件侧 USB 打开、握手、请求和错误累计计数。

`firmware_elf_sha256` 是 ESP-IDF 应用描述信息中的 ELF 哈希，不是整个烧录 `.bin` 文件的 SHA-256。Agent 的 `device_boot_changes` 只统计它已观察到的设备启动 ID 变化；初次连接不计作重启，同一启动期间的 USB 重连也不计作重启。Agent 自身重启会清零这个计数。

断线后 Agent 保留最后一次快照供排查，但 `usb.device_stale` 会变为真。重连后，必须收到当前 USB 会话的新快照才恢复为有效；120 秒未更新也会标记为过期。旧固件没有该消息时，`usb.device` 为 null，不会生成虚假的设备状态。设备不连接 Agent 时不会向电脑留下这些运行记录。

## 连续运行记录

等待 Luna 连接 Agent 后，在仓库根目录运行：

```powershell
.\pc-agent\monitor-link.ps1 -DurationSeconds 28800 -IntervalSeconds 10 -RequireDeviceDiagnostics
```

CSV 除 Agent 链路状态外，还包含设备启动 ID、运行时间、固件哈希、内存和固件 USB 错误计数。设备启动 ID 变化或 USB 错误计数增加会被记录为异常；启用 `-RequireDeviceDiagnostics` 后，缺失或过期的设备快照也会使记录在结束时报告失败。旧固件仍可不带该参数使用原有 Agent 链路记录。

判断内存泄漏时需要比较一段稳定负载下的当前空闲量趋势。历史最低空闲量可能因一次天气请求、解码或界面重建而下降，不能据此直接判定泄漏。

## 验证记录

2026-10-02：30 项 PC Agent 单元测试通过，包括坏诊断消息不覆盖旧数据、状态服务继续工作、USB 重连后的旧快照标记、设备启动 ID 变化、快照过期，以及慢 Codex 刷新不阻塞缓存读取。

ESP-IDF 6.0.2 构建通过，经 COM27 烧录并完成哈希校验。应用 `.bin` SHA-256 为 `97896D7EEA82F478D3624CDEAE1315D692B83E81B093A91B0CDB9C13E05B93D1`；COM28 实际收到的 ELF SHA-256 为 `4cbf7601fcc5c23c101c301e941872dca9600ace13d47857630453418fca7561`。

首轮实机采样揭示 Codex 同步读取会等待 App Server 超时，超过固件 2.5 秒状态请求期限，造成 USB 超时及迟到应答。现已改为后台刷新，USB/HTTP 状态读取只访问缓存；数据缺失、失败或过期时明确返回不可用。Codex 服务本身仍可能超时，本次修复是隔离等待，不代表额度服务恢复。加载改动后稳定采样 30 秒、7 次记录无新增错误，固件历史失败/超时/协议错误均保持 11 未增长。一次紧接 Agent 启动的采样正确报告首个样本尚无设备快照；不能把该记录称为全程通过。

保持 Agent 运行，通过 COM27 的 RTS/EN 主动复位实板：设备启动 ID 从 `15ddb40ebda806d6` 变为 `45da34296b2a5a6d`，设备运行时间从 826 秒降至 5 秒，Agent 的 `device_boot_changes` 从 0 变为 1；COM28 自动重新握手，ELF 哈希未变，新的设备错误计数为 0。Agent 在设备重新枚举期间记录 1 次断线与 3 次发现重试错误，属于本次主动复位过程；复位原因实测返回 `power_on`，因此判定重启同时使用启动 ID 而非只依赖原因枚举。调试 UART 随后已关闭。

主动复位恢复后再次稳定采样 30 秒、7 次记录无新增错误，设备失败/超时/协议/队列/发送错误均为 0；稍后运行时间 161 秒时这些计数仍为 0，Wi-Fi 已恢复在线。监测脚本也在 Windows PowerShell 5.1 下完成 3 次实机采样、0 次异常。

另用模拟诊断响应验证 CSV 异常判定：过期快照和相邻采样的启动 ID 变化均被正确记录并使脚本报告失败；模拟没有改变真实设备状态。
