# 常亮、低负载待机

更新：2026-10-03。用户确认双缓冲版本待机返回/显示“没问题了”。

## 当前策略

- 保留 180 秒自动待机、顶部空白手动待机、首次触摸仅唤醒。
- 底部仅显示“慢慢来，你已经在向前了。”，保留日期、完整睡猫及三个错峰上浮/淡出的 ZZZ。
- CPU 固定 360 MHz。屏幕亮度、MIPI/PSRAM 扫描时钟和 BLE/Wi-Fi 不变；不进入整机 light/deep sleep。
- 待机 UI 200 ms、刷新轮询 50 ms；ZZZ 5 Hz，表针/睡猫帧 1 Hz。隐藏卡片不布局、背景采集继续缓存。
- 返回恢复 33 ms UI / 15 ms 刷新，并立即更新所选卡片真实数据。场景切换一次完整重绘；不逐帧全屏刷新。

这是减少处理活动，不是已测量的整机节电幅度。屏幕/背光/无线仍耗电，不承诺功耗减半。

## 已排除的策略

180 MHz 实机降频试验触发 `lcd.dsi: can't fetch data from external memory fast enough, underrun happens`，导致设备蓝屏、触摸虽记录恢复但画面没有可靠恢复。已撤回，禁止在正常 DSI 扫描中切换 CPU 配置或释放驱动锁。该试验不是 Windows 蓝屏或蓝牙故障。

固定 360 MHz 后，用户确认能正常返回，但卡片还有淡时钟数字；root 完整重绘本身未消除它。随后切换支持的 DOUBLE_DIRECT 绘制路径，用户反馈“没问题了”。不据此把所有残影归因于物理屏幕，也不声称已独立定位到具体 DMA/cache 缺陷。

## 已验证基线

通过物理反馈的镜像：9,750,320 bytes，SHA-256 `7be6bac9747b7fbb3e6e0552bca0ce412cc6bd1ccf5aae008cf618bfa9a75eac`。app-only 写入通过整镜像校验，BLE 恢复真实数据。UART 记录 CPU=360 MHz、显示 mode=3、ACTIVE→STANDBY→ACTIVE，错误标记 0，观察结束释放 COM27。

本轮进一步的隐藏卡片/差异刷新优化结果见[性能与清理](ui-performance-20261002.md)。物理亮度、触摸和长期行为不能仅由桌面 LVGL 模拟测试证明。
