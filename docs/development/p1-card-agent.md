# P1 卡片主页与 Windows 助手实机验证

> 本页记录三卡版本；当前四卡轮播与最新构建步骤见
> [壁纸时钟卡实机验证](p1-clock-card.md)。

## 验证目标

本轮验证第一条完整的“触摸屏 → Wi-Fi → Windows”控制链路：

- 面板以横向轮播显示 Codex 综合、音乐和天气三张卡片；
- Codex 综合卡同时显示额度与当前项目；
- 面板通过局域网发现 Windows 助手；
- 音乐卡片可以向 Windows 发送上一首、播放/暂停和下一首命令；
- 硬件诊断页和卡片主页可以相互切换；
- 尚未接入的数据明确显示为待接入，不显示虚构内容。

本阶段先验证通信和控制是否可靠。网易云歌曲名称、歌手和封面已在后续的
音乐卡版本中接入；Codex 额度、联网天气和语音控制仍将逐项接入。

## 验证前准备

请确认以下条件：

- ESP32-P4 面板和 Windows 11 电脑连接同一个 Wi-Fi；
- 开发板使用 USB TO UART 接口连接电脑，当前串口为 `COM27`；
- 网易云音乐 3.1.34 已打开，并准备好一个可播放的歌曲列表；
- 使用现有的 ESP-IDF v6.0.2 环境：`D:\.espressif\v6.0.2\esp-idf`；
- 电脑端没有其他程序占用 TCP 端口 `8765`。

电脑当前的局域网地址和配对令牌已经保存在 Git 忽略的本地配置文件中，
不会提交到代码仓库。如果电脑以后获取了新的 IPv4 地址，需要在
`idf.py menuconfig` 中修改“Windows companion IPv4 address”，然后重新构建
并烧录固件。

## 第一步：启动 Windows 助手

首次使用真实媒体状态同步时，先在项目根目录准备一次运行环境：

```powershell
.\pc-agent\setup-agent.ps1
```

以后打开第一个 PowerShell 窗口，在项目根目录执行：

```powershell
cd D:\Documents\ChatGPT\ESP32-P4-4B-Luna
.\pc-agent\start-agent.ps1
```

窗口出现以下提示代表服务已经启动：

```text
Luna agent listening on http://0.0.0.0:8765
Windows media session synchronization is active.
Press Ctrl+C to stop.
```

验证期间不要关闭这个窗口。面板每次读取状态或发送音乐命令时，这里都会
出现一条 HTTP 访问记录。

首次运行时，Windows 防火墙可能询问是否允许 Python 访问网络。请选择
**允许访问专用网络**。不需要开放公用网络。

可以在另一个 PowerShell 窗口执行本机健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8765/health
```

预期返回内容中包含：

```text
ok               : True
protocol_version : 1
```

健康检查接口不包含私人数据，也不需要配对令牌。状态和控制接口均需要配对
令牌。

## 第二步：构建并烧录完整固件

保持 Windows 助手运行，再打开第二个 PowerShell 窗口，在项目根目录执行：

```powershell
cd D:\Documents\ChatGPT\ESP32-P4-4B-Luna
.\scripts\build-firmware.ps1 -Action flash-full -Port COM27
```

`flash-full` 会完成以下操作：

1. 使用 ESP-IDF v6.0.2 构建固件；
2. 合并引导程序、分区表和 Luna 应用；
3. 将完整镜像从地址 `0x0` 写入 ESP32-P4；
4. 自动复位开发板。

这个方式可以避免只烧录应用程序或写入错误地址引起的
`invalid header` 循环报错。

当前构建产物：

| 项目 | 数值 |
| --- | --- |
| 完整镜像 | `firmware/luna-panel/build/luna_panel_full.bin` |
| 文件大小 | `1,931,712` 字节 |
| SHA-256 | `74DBF2DDD58D4002C8A010497CAE6B337FA63182CCF55FC1762718CAB631364F` |

## 第三步：观察启动过程

烧录完成后，如需查看串口日志，执行：

```powershell
.\scripts\build-firmware.ps1 -Action monitor -Port COM27
```

按 `Ctrl+]` 退出串口监视器。

正常情况下，屏幕和连接状态应按以下顺序变化：

1. 显示 720×720 横向滑动卡片主页；
2. Wi-Fi 状态从连接中变为在线；
3. Windows 助手运行时，PC 状态约在 3 秒内从检查中变为就绪；
4. Codex 综合卡右侧显示当前项目 `Luna`；
5. Codex 额度和天气数据未接入时显示待接入状态。

TF 卡自动测试现在默认关闭，未插卡时不会再主动挂载，也不影响本轮验证。

## 第四步：验证音乐控制

先在电脑上打开网易云音乐，手动播放任意歌曲，然后在面板音乐卡片上依次
测试：

1. 点击播放/暂停，确认网易云切换播放状态；
2. 点击下一首，确认网易云切换到下一首；
3. 点击上一首，确认网易云切换到上一首；
4. 连续快速点击时，确认界面没有卡死或重启。

当前音乐卡片会从 Windows GSMTC 媒体会话读取网易云的真实播放状态。点击
播放/暂停后，按钮会短暂禁用，Windows 助手根据真实状态明确执行播放或暂停，
固件随即重新读取状态并更新按钮文字。当前构建还会显示 UTF-8 中文曲名、歌手
和 JPEG 专辑封面，详细验证见 `p1-music-card.md`。

## 第五步：验证页面切换

1. 点击主页中的 `Diagnostics` 按钮；
2. 确认可以进入原有硬件诊断页面；
3. 测试触摸计数、扬声器和麦克风电平；
4. 点击 `Home` 返回卡片主页；
5. 往返切换三次，确认没有闪退、黑屏或触摸失效。

## 故障排查

### PC 状态一直显示检查中或离线

依次检查：

1. Windows 助手窗口是否仍在运行；
2. 本机健康检查是否返回 `ok : True`；
3. 面板和电脑是否连接同一个 Wi-Fi；
4. Windows 当前 IPv4 地址是否仍与固件配置一致；
5. Windows 防火墙是否允许 Python 访问专用网络；
6. 串口日志中是否出现 HTTP 超时、连接拒绝或鉴权失败。

### 串口反复显示 `UI event queue is full`

2026-09-25 的首版 P1 固件存在两个连续问题。第一版中麦克风电平事件会占满
普通 UI 队列；第二版虽然分离了麦克风队列，但错误地把播放按钮的文字对象
再次当成按钮查找子对象，最终得到空指针。LVGL 的空指针断言会停在无限循环，
随后触发任务看门狗，表现为 PC 一直停在检查中、按钮无响应、队列再次堆满并
周期性复位。当前固件已直接保存正确的播放文字对象，并保留分离后的麦克风
队列。出现这组日志时，请重新执行 `flash-full`，确认烧录的是最新完整镜像。

### 按钮有触摸反馈，但网易云没有动作

依次检查：

1. 网易云是否已经打开并存在可播放队列；
2. 电脑键盘上的系统媒体键能否控制网易云；
3. 点击按钮时，Windows 助手窗口是否出现 `POST /api/v1/actions`；
4. 是否有其他播放器抢占了 Windows 的系统媒体会话。

### 点击音乐按钮后出现 `Stack protection fault` 并重启

2026-09-25 的媒体状态首版在 `agent_actions` 任务栈上分配了 4 KB HTTP 响应
缓冲区，进入 lwIP 网络调用时可能越过 6 KB 任务栈边界。当前版本已经把响应
缓冲区移到堆上，并把控制任务栈增加到 10 KB。播放/暂停、上一首和下一首均
使用同一条修复后的控制路径。

### 歌名或歌手显示乱码

当前固件的曲名和歌手字段使用思源黑体 16 像素中文字库，并在接收端按完整
UTF-8 字符边界截断超长文本。如果仍然乱码，请确认已经烧录最新完整镜像，并
重新启动 Windows 助手，使其返回原始 UTF-8 曲名和歌手。

### 再次出现 `invalid header`

不要把 `luna_panel.bin` 单独写入地址 `0x0`。重新执行：

```powershell
.\scripts\build-firmware.ps1 -Action flash-full -Port COM27
```

### COM27 无法打开

关闭其他串口监视器和烧录工具后重试。如果 Windows 改变了端口号，在设备
管理器确认新端口，并通过 `-Port COMx` 指定。
