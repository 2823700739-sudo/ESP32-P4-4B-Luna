# P2 离线语音唤醒与固定命令实机验证（历史记录）

> 2026-09-27 起，当前固件已移除离线语音控制。本页只供查阅旧版本，
> 请勿按本页烧录或验收当前固件。当前步骤见
> [无语音版本实机验证](no-voice-validation.md)。

## 本轮目标

本轮在 ESP32-P4 上接入 ESP-SR 离线语音链路，先验证“唤醒一次、识别一条固定
命令、执行并显示结果”的完整流程。语音音频只在开发板本地处理，不上传到网络。

当前开发验证使用 ESP-SR 自带的中文唤醒词 **“Hi 乐鑫”**。产品目标唤醒词仍是
**“Luna”**，本轮没有把其他发音冒充成 Luna。乐鑫官方的自定义唤醒词流程需要
提交语料并由官方训练；客户自行提供语料时要求至少 2 万条，文档给出的周期约
2～3 周，并标注为付费服务。因此先用内置词验证硬件、音频和命令链路，避免在
链路尚未通过前投入自定义模型费用。

参考资料：

- [ESP-SR WakeNet 唤醒词引擎](https://docs.espressif.com/projects/esp-sr/zh_CN/latest/esp32/wake_word_engine/README.html)
- [乐鑫自定义唤醒词流程](https://docs.espressif.com/projects/esp-sr/zh_CN/latest/esp32/wake_word_engine/ESP_Wake_Words_Customization.html)
- [ESP32-P4 MultiNet 命令词识别](https://docs.espressif.com/projects/esp-sr/zh_CN/latest/esp32p4/speech_command_recognition/README.html)

## 已接入内容

- ESP-SR `2.4.7`；
- WakeNet9 内置唤醒模型 `wn9_hilexin`；
- MultiNet7 中文命令模型 `mn7_cn`；
- ES7210 麦克风以 16 kHz、16 bit、单通道送入 AFE；
- 语音状态显示在主页顶部，诊断页继续显示实时麦克风电平；
- “播放歌曲”使用明确播放动作，Windows 助手根据真实媒体会话执行，不用盲目
  发送播放/暂停切换键；
- 语音模型写入独立的 `model` 分区，偏移为 `0x620000`。模型映射结束地址
  保持在 16 MB 内，兼容 ESP32-P4 默认的 24 位 Flash 映射模式。

## 当前命令表

每条命令都要先说一次“Hi 乐鑫”，看到界面进入识别状态后，在 6 秒内说一条
命令。识别成功后自动回到等待唤醒状态。

| 类别 | 可以说的话 | 执行动作 |
| --- | --- | --- |
| 音乐 | 播放歌曲 | 明确开始播放 |
| 音乐 | 暂停 | 明确暂停播放 |
| 音乐 | 上一首 | 网易云上一首 |
| 音乐 | 下一首 | 网易云下一首 |
| 信息 | 查看天气 | 切到天气卡 |
| 信息 | 查看额度 | 切到 Codex 综合卡 |

“播放歌曲”和“下一首”仍是正式命令。为提高不同语速和发音下的成功率，固件还给
这两个动作加入了“开始播放”和“播放下一首”两个备用说法；“暂停”也可说成
“暂停播放”。这些备用说法映射到相同动作，不会增加界面功能项。

## 第一步：重启 Windows 助手

“播放歌曲”使用明确的 `music.play` 接口。先在旧助手窗口按
`Ctrl+C`，然后在项目根目录启动新版：

```powershell
cd D:\Documents\ChatGPT\ESP32-P4-4B-Luna
.\pc-agent\start-agent.ps1
```

保持网易云音乐打开，并先用鼠标确认正常播放和切歌。

## 第二步：完整烧录

本轮必须使用 `flash-full`。普通的旧版应用烧录不包含位于 `0x620000` 的语音
模型，届时界面会报告模型不可用。完整镜像约 9 MB，仍会比不含语音模型的
版本烧录时间更长。

```powershell
cd D:\Documents\ChatGPT\ESP32-P4-4B-Luna
.\scripts\build-firmware.ps1 -Action flash-full -Port COM27
```

烧录完成后查看串口：

```powershell
.\scripts\build-firmware.ps1 -Action monitor -Port COM27
```

按 `Ctrl+]` 退出串口监视器。

## 第三步：启动检查

正常启动时重点查找以下内容：

```text
Offline voice ready: models=..., feed=..., fetch=...
Command threshold 0.12, result=...
---------------------ACTIVE SPEECH COMMANDS---------------------
```

主页语音状态应显示 `唤醒词：Hi 乐鑫`。诊断页的麦克风条应随正常说话明显变化，
不需要贴近麦克风或拍打麦克风孔。

串口打印的活动命令会显示无声调拼音，例如 `bo fang ge qu`；这是 MultiNet7
中文模型的输入格式。面板识别成功后仍显示对应的中文命令。

本轮共有 6 个对外命令。由于播放、下一首和暂停各有备用说法，串口会打印 9 条
活动短语，其中相同动作的短语具有相同 command ID。识别成功日志会包含
`probability`、VAD 语音帧数和最大输入音量；超时日志也会打印 VAD 语音帧数和
最大输入音量，用来区分“没有收到有效语音”和“收到语音但命令不匹配”。

如果出现 `Speech model partition is empty`，说明没有完成整包烧录；重新执行
`flash-full`。如果出现 `Command model init failed`，请保留从语音模型加载开始到
报错结束的完整串口日志。

如果串口仍显示 `Address 0x00f20000 is out of range for 24bit flash mapping`，说明
烧录的还是旧分区镜像。修正版模型分区是 `0x620000`，完整镜像 SHA-256 应与本文
末尾一致；重新执行一次 `flash-full`，不能只烧录应用程序。

## 第四步：逐条验证

建议先在安静环境、距离设备约 0.5～1 米处测试：

1. 说“Hi 乐鑫”；
2. 确认主页显示 `请说命令`，串口出现 `Wake word detected`；
3. 在 6 秒内说“查看天气”；
4. 确认切到天气卡，串口出现 `Command detected`；
5. 对命令表中的每条动作重复以上流程；
6. 分别在“已经播放”和“已经暂停”状态下说“播放歌曲”，确认已播放时不会暂停，
   暂停时会继续播放；
7. 说“暂停”，确认网易云停止播放；
8. 如果“播放歌曲”或“下一首”仍不稳定，再分别测试备用说法“开始播放”和
   “播放下一首”；
9. 唤醒后保持安静，确认约 6 秒后显示 `未识别到命令`，随后还能再次唤醒。

音乐命令需要电脑在线并运行 Windows 助手。电脑休眠或助手关闭时，本地卡片
导航仍应工作，音乐命令会显示无法确认执行；这不应导致开发板复位。

## 第五步：桌面场景与稳定性验证

基础命令通过后，再把设备放回电脑旁的实际位置：

1. 电脑音箱静音，连续唤醒并执行 20 次，记录成功次数；
2. 电脑音箱以日常音量播放音乐，再执行 20 次；
3. 分别从正面 0.5 米、1 米和日常坐姿位置测试；
4. 连续交替执行上一首、下一首和播放歌曲共 30 次；
5. 语音切换三张卡片 20 次；
6. 保持 Windows 助手、网易云和天气同步运行 30 分钟；
7. 串口确认没有任务看门狗、栈保护、SDIO 不可恢复状态或自动复位。

电脑音箱的播放信号目前没有作为板端 AEC 参考输入，因此音乐外放时的唤醒率
需要以实测结果为准。记录距离、音箱音量和成功次数，下一轮据此调整麦克风
增益、AFE 模式或命令词。
