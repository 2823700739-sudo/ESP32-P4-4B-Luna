## 1. 产品定位与范围

Luna 是放在 Windows 电脑旁的友好触摸桌面助手，不是扩展显示器或完整音乐客户端。
日常只需设备供电与蓝牙连接，不要求连接电脑 OTG 数据线或填写电脑 IP。
Windows 仍需安装并运行当前用户的配套 Agent；一次安装、配对后自动启动和重连是交付目标，
而非承诺无需任何 PC 软件。无线通信不提供电力，现有硬件仍需外部供电。

| 功能 | 首版内容 | 数据来源与通道 |
| --- | --- | --- |
| 音乐控制卡 | 固定播放器外观；标题、歌手、播放/暂停、上一首、下一首、音量、静音 | Windows GSMTC / 系统音量，经 BLE |
| 天气卡 | 地点、天气图标、当前温度、体感、湿度等；更新时间和缓存标记 | 面板通过 Wi-Fi 直连 Open-Meteo |
| 时钟卡 | 开机默认卡；大数字时间、日期、星期及宠物 | BLE 优先、Wi-Fi 备用校时，面板本地走时 |
| Codex 额度卡 | 5 小时/周两条剩余额度条；当前 VS Code 项目 | 额度来自 Codex，项目来自 VS Code，经 Agent / BLE |
| 电脑状态卡 | CPU/GPU 双圆环、对应温度；内存/显存使用率与已用/总量横条 | Windows 采集器，经 BLE；不支持的指标标明不可用 |
| 像素宠物 | 四周自主活动、点击回应；不随业务状态触发动作 | 本地素材、动画与交互，不传图片流 |

首版保留单张大卡为主的五卡横向滑动，开机固定进入数字时钟卡；宠物不是第六张卡。
视觉实现严格以获批 `docs/design/preview` 的 HTML/CSS/素材为基准，不再另行简化设计。
左右各保留预览中的 30×382 装饰性卡片边缘，不扩展成露出相邻卡片内容的新布局。
后续明确变更同步到预览与固件：音乐底部只保留右侧音量图标，弹层顶部静音、下方竖向音量条；
额度条改为 542×22，标签 20 px、字间距 2 px，移除每条下面的提示语；小猫使用完整 72×72 绘制区域。
小猫招呼语作为独立浮层并限制在屏幕内，避免外溢子对象局部刷新裁切；切卡保留滑入，
移除整卡缩放/透明度叠加以降低绘制开销。背景星星低频更新，不降低输入或宠物刷新频率。
设备常亮，不自动降亮度；支持自动/手动待机，待机减少处理负载、首触摸只唤醒。CPU 始终保持 360 MHz，
通过局部刷新、数据差异更新和字体并发解码保护优化流畅度。Noto 开放字体替代网页使用的
Windows 字体，保留文字层级/间距，不将不同字体或不同渲染器声称为逐像素相同。
不恢复离线语音，不增加日历、相册、自由 AI 对话、
任意脚本、手机配置或 OTA。诊断页是维护入口，不作为第六张业务卡。
系统音量与播放器音量必须标明区别，沿用现有系统音量控制。

## 2. 可行性结论与当前进度

整体可实现，且取消封面后 BLE 只传小规模结构化数据，不传图片或屏幕帧。
关键验证门槛是板载 C6 的蓝牙控制器固件、P4 的 Hosted / NimBLE 配置，以及 Windows
蓝牙适配器的实测兼容性。蓝牙也会受距离、2.4 GHz 干扰和休眠影响，不能预先承诺比 USB 更稳定。

截至本次代码盘点：当前分支为 `codex/usb-r2`，实现基线提交 `30f85c3`。

## 3. 新架构与数据边界

```text
VS Code 项目桥接 → Windows Agent（媒体、额度、当前工程、硬件指标、系统时间）
        ↕ BLE GATT：小消息、状态通知、动作请求与结果
ESP32-P4（NimBLE Host、业务逻辑、LVGL、本地时间与缓存）
        ↕ ESP-Hosted / SDIO
板载 ESP32-C6（BLE Controller + Wi-Fi）
        ↕ Wi-Fi HTTPS
Open-Meteo（天气） / NTP（BLE 不在线时的备用校时）
```

- P4 本身没有内置蓝牙射频，使用板载 C6，不是给 P4 直接打开 BLE 就能工作。
- Windows 为 BLE Central，Luna 为 Peripheral，使用自定义 GATT 服务；不是蓝牙串口或蓝牙音箱。
- 状态、时间与动作沿用 Agent 的业务适配器，不通过 BLE 发送 UI 图像或音乐音频。
- Wi-Fi 首版负责天气与备用校时，不回退到 PC HTTP；BLE 有效时优先采用电脑时间。
- USB TO UART 调试/烧录与外部供电保留；“取消 OTG”指取消应用通信和相关启动，
  不破坏芯片下载恢复能力。HID/UAC/扩展屏暂不立项。
- 旧 USB 实现已经备份并移出当前源码，新默认固件不初始化业务 CDC，
  新默认 Agent 不打开 CDC/COM28，也不启动面板可访问的 PC HTTP 回退。
- 独立采集线程处理 Codex/传感器/天气，不能阻塞 BLE 动作应答。

## 4. 状态、时间与真实性

### 4.1 音乐

所有歌曲使用同一套本地唱片/播放器图形，不下载、不缓存、不传输、不解码封面。
播放时唱片轻微旋转，暂停时停转，不宣称是实时音频频谱。
音量控制展开时，点击滑块控制区域以外立即收起；如果点击其他按钮，收起后仍执行该按钮动作，
不吞掉本次点击。卡片滑动和点击宠物也需要在不冲突的事件顺序下收起音量控制。
快速点击沿用“立即反馈、按顺序处理、权威状态校正”；已发出而未确认的动作不能重放。
无媒体会话、PC 离线或接口不可用时控制禁用并显示原因，不把旧状态当成实时播放状态。

### 4.2 Codex

两条额度分别显示“5 小时剩余 xx%”“周额度剩余 xx%”，计算为
`clamp(100 - usedPercent, 0, 100)`，不是已用百分比或 API 余额。
以接口实际 `windowDurationMins` 为准；300 分钟与 10080 分钟才能分别标为 5 小时与周。
缺失一个窗口不能隐藏另一个有效窗口；未知显示“-- / 暂不可用”，不能当成 0%。

项目区仅展示最近活动的 VS Code 项目。用户明确选择当前编辑工程，不要最近 Codex 会话工作区。
跟随最近操作的 VS Code 窗口，切到浏览器时保留，切到另一工程窗口后更新。
首版已实现只读窗口来源：验证前台进程为 Code.exe，解析标准工作区窗口标题，并保留最近识别名称。
需将工程窗口置前一次；自定义标题、单文件或未识别工程时明确留空，不拿线程 cwd 顶替。
精确全路径、多根工作区活动文件定位仍需后续 VS Code 扩展桥接，当前不声称已完成。

### 4.3 时钟与常亮交互

BLE 在连接成功、电脑唤醒、时间/时区变化时同步 UTC 与时区信息，并周期校准。
时钟卡使用统一时间服务；本地秒数无需蓝牙每秒发消息。
断开 PC 后，只要设备仍供电且已有有效时间就继续走时；PC/BLE 不在线时允许 Wi-Fi NTP 校时，
让设备单独供电、电脑关机时仍可作为独立时钟。冷启动且两个来源都不可用时显示“等待校时”，
不把 NVS 里的旧时间当成当前时间。共享时间服务统一选择来源，防止 BLE 与 NTP 来回覆盖。

用户最新确认恢复 180 秒自动待机，并增加顶部空白区域（720×720 的 y < 135，卡片上方）
点击手动进入圆盘时钟；卡片内、两侧和底部空白区域均不触发。Logo、蓝牙状态和小猫除外。
触摸、拖动与滑动重置计时；按钮、文字/图案、小猫、音量操作和切卡不触发手动待机。
音量弹窗外的空白点击先收起弹窗，再次空白点击才进入时钟。后台数据和蓝牙重连不重置计时。
待机保持原亮度与 360 MHz 显示安全频率；180 MHz 实机试验触发 DSI underrun/蓝屏，已撤回，
不在显示扫描期间切换硬件时钟或绕过驱动锁。以暂停隐藏卡片绘制与低频小区域动效减少处理活动；
不开启 light/deep sleep，不断开 BLE/Wi-Fi。整机节电幅度尚无电流测量，不声称 CPU 或总功耗减半。
仅 5 Hz 更新三个错峰上浮/淡出的 ZZZ；时针/分针/秒针与睡猫两帧每秒更新。暂停隐藏卡片布局与动画，
后台采集仍更新缓存，返回卡片立即对齐真实数据。底部两行技术说明改为一句“慢慢来，你已经在向前了。”
圆盘时钟显示时分秒针，使用同一真实时间服务；未校时时隐藏指针、显示等待。
首次触摸只唤醒到进入前卡片，不穿透触发音乐；再次触摸才正常操作。
宠物沿四周自主活动，可点击互动；短暂休息后原位继续，待机隐藏行走宠物并暂停活动路径，另显示完整睡猫。
不遮挡文字和主要按钮，不因音乐或额度变化频繁打断用户，不把宠物点击和卡片滑动混为一谈。

### 4.4 天气与电脑状态

天气继续按地点独立刷新；Agent 关闭时仍可通过 Wi-Fi 更新。
首次地点配置需持久化，不能把电脑每次在线当成天气启动前提。

CPU/RAM 可优先用 Windows 用户态采集；GPU 使用率需要按厂商/驱动提供适配。
温度、风扇和部分显存指标不是所有电脑都可读取，支持时显示，不支持时留空并说明。
断线/过期数据标明“上次数据”，缺失传感器不能画成 0% 或 0°C。

## 5. UI 风格与开源参考

采用统一的“月夜桌面伙伴”方向：深蓝灰底、柔和圆角、薄荷绿/暖橙/淡紫点缀、
清楚的大数字、小幅弹性动效。每张卡有自己的视觉识别，但按钮、文字层级、
状态标记与卡片边距一致。避免密集仪表与满屏大动画。

研究与具体布局见 [UI 开源参考和设计基线](../design/ble-ui-references.md)。
按用户确认的流程，先研究优秀 GitHub 案例并结合 Luna 设计，再提供五卡与宠物的完整
UI 交互预览，用户确认效果后才落地固件；不采用“先堆功能、最后改配色”的交付方式。
优先沿用当前 LVGL 9.3.0 的原生组件，不整体移植别的平台 Demo，
不直接复制授权未核实的素材。音乐卡始终保留固定播放器外观。

B0 是实施前的关键门槛。若需要更新 C6 固件，先确认烧录口、备份和恢复方法；
不能把更新 P4 当成已经更新 C6，也不能因失败自动恢复为 OTG 产品路线。
具体当前配置与待验收项见[当前开发状态](../development/current-status.md)。

## 7. 首版验收目标

以下是完整交付目标；部分 BLE/音乐门槛已验证，但不能据此视为完整验收。
逐项证据与未完成项见[当前开发状态](../development/current-status.md)和 [B1 记录](../development/b1-music-bringup.md)：

- 完成一次安装/配对后，Windows 登录自动启动 Agent，Luna 无 OTG 数据线可接入；
  可使用 UART 调试线或电源供电，明确与业务通信分离。
- 新默认 Agent 不扫描/占用 CDC；连接电脑 OTG 口不会启动旧业务协议。
- 在正常桌面距离，触摸反馈目标 ≤150 ms，动作到达 Agent 目标 ≤300 ms（记录分位数）；
  播放器自身异步处理时间另测，不能承诺所有播放器在 300 ms 内完成。
- 快速连续切换播放/暂停，最终状态与有效用户意图一致；断线/超时不重复执行切歌等动作。
- 蓝牙关闭/开启、Agent 重启、设备复位、Windows 休眠/唤醒各 20 次恢复测试，
  不需要手改 COM/IP，不重放上个会话的动作。
- Wi-Fi 天气刷新与 BLE 音乐控制并发，界面不卡住；Wi-Fi 断网不影响 PC 控制，
  BLE 断线不影响独立天气。
- 两条额度分别验证完整、单窗口缺失、实际窗口不同、过期/认证失败和 PC 离线。
- VS Code 两个工程窗口切换、多根工作区、空窗口和自定义标题，已识别项目来自最近前台工作区，不能识别时明确不可用，
  不用最近 Codex 会话替代当前工程；该来源故障不影响额度区域。
- 音量条外点击立即收起且其他按钮动作执行；滑块拖动和滑动卡片没有冲突。
- 电脑 CPU/GPU/RAM 与同口径 Windows 数据对照；采集失败正确显示不可用，温度不作为跨硬件硬门槛。
- 闲置 3 分钟进入模拟表盘待机；顶部空白点击可提前进入。亮度不变，第一次触摸只唤醒并返回原卡；宠物完整显示且移动连续，
  不遮挡或抢走控件触摸；切卡无旧对象访问。
- 已校时的设备断开 BLE 后一小时正常走时；电脑关机、设备冷启动时可通过 Wi-Fi 校时；
  两个来源均不可用时明确提示，BLE 恢复后按来源优先级重新校准。
- 连续切卡 100 次、持续运行 8 小时，检查内部 RAM/PSRAM、任务栈、重启与连接恢复；
  无崩溃、持续泄漏和永久重连。取消封面不等于已证明内存足够。

记录固件与 Agent 哈希、C6 固件版本、Windows 适配器、测试条件和日志。
单元测试/构建通过不能替代显示、触摸和无线实机验收。

## 8. 安全、风险与取舍

- BLE 不是“附近就可控制”：首次配对需设备侧确认，启用加密、绑定与已授权设备校验；
  公开 UUID 或设备名称不能作为认证。忘记绑定有明确本地确认流程。
- 只允许现有白名单音乐/音量操作，不开放任意文件、程序或键盘注入。
- 账号凭据留在 Windows；配对、Wi-Fi、地点等本地配置不提交仓库。
- 温度扩展若需管理员权限或额外组件，单独说明并征得同意；不默认提权或安装驱动。
- Wi-Fi 与 BLE 共用 C6 无线资源，需要实测并发，不宣称蓝牙免受无线干扰。
- 不把模拟动画包装为实时频谱，不把最近线程工作区包装为正在操作的项目。
- 若蓝牙硬件/驱动阻塞，先报告具体证据和备选方案，再决定是否增加外置无线模块；
  不擅自恢复有线或 Wi-Fi PC 回退。
- 继续暂停语音、OTA、扩展屏和新的 OTG 实验，先完成本次首版。
